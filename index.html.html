01

Entiende las herramientas

Tres nombres parecidos, tres funciones diferentes. Entender esta distinción evita confusiones.

Git

Es el sistema de control de versiones. Registra los cambios que decides guardar en el historial y permite consultar versiones anteriores.

GitHub

Es una plataforma online donde puedes alojar repositorios Git, compartir proyectos y colaborar con otras personas.

GitHub Desktop

Es una aplicación visual para trabajar con Git sin escribir comandos en la terminal para las tareas básicas.

Tres conceptos clave

Repositorio: proyecto e historial. Commit: registro de cambios. Rama: línea de trabajo separada.

Ejemplo: el repositorio contiene tu portafolio; un commit registra una versión y una rama te permite probar una sección nueva antes de integrarla.

Guardar un archivo no crea automáticamente un commit. Crear un commit tampoco significa que ya esté publicado en GitHub.

02

Prepara tu entorno

Utiliza enlaces oficiales y evita descargar instaladores desde páginas de terceros.

  1. Crea una cuenta en GitHub.com y completa la verificación que se solicite.
  2. Descarga GitHub Desktop desde desktop.github.com e instala la versión de tu sistema operativo.
  3. Abre la aplicación, inicia sesión con GitHub.com y completa la autorización en el navegador.
  4. Comprueba que puedes acceder a las opciones para crear o clonar un repositorio.
Seguridad: no publiques contraseñas, tokens ni claves API. Activa la autenticación en dos pasos.
03

Crea tu primer proyecto

Construiremos un portafolio básico con un README. No necesitas programar.

  1. En GitHub Desktop, elige crear un repositorio nuevo en tu ordenador.
  2. En Name, escribe mi-primer-proyecto. En la descripción: Mi primer proyecto para aprender Git y GitHub.
  3. Activa la opción para inicializar el repositorio con un README y selecciona una carpeta local fácil de encontrar.
  4. Pulsa Create repository. Los nombres pueden variar según idioma y versión.
  5. Abre README.md desde la carpeta del proyecto y sustituye su contenido por esta plantilla.
# Mi primer proyecto

## Sobre mí
Estoy aprendiendo a utilizar Git y GitHub
para organizar mis proyectos y controlar
los cambios que realizo.

## Mis objetivos
- Aprender los fundamentos de Git.
- Crear proyectos propios.
- Aprender a colaborar con otras personas.

## Mi primer reto
Crear un repositorio, registrar mis cambios
y aprender a trabajar con ramas.
  1. Guarda el archivo y vuelve a GitHub Desktop. Revisa los cambios.
  2. Escribe un resumen como Add personal README y crea el commit.
  3. Selecciona Publish repository, revisa la privacidad y confirma la publicación.
Comprueba el resultado: abre el repositorio en GitHub.com. Debes ver el README y su contenido. Crear un repositorio local no significa que ya esté publicado.
04

Registra y publica versiones

El flujo esencial es modificar, revisar, registrar y publicar.

Añade al final de tu README:

## Lo que he aprendido
Ahora sé crear un repositorio y publicar
mis primeros cambios en GitHub.
  1. Guarda el archivo y vuelve a GitHub Desktop. En Changes, revisa las líneas modificadas.
  2. Escribe Add learning progress to README en el resumen y crea el commit.
  3. Selecciona Push origin si aparece, para enviar los commits locales pendientes a GitHub.
  4. Abre History para localizar el commit.
ComandoPara qué sirve
git statusConsulta el estado de archivos y cambios pendientes.
git add README.mdPrepara los cambios del README para el próximo commit.
git commit -m "Actualiza README"Registra los cambios preparados en el historial local.
git pushEnvía commits al repositorio remoto.
git pullDescarga e integra cambios remotos en la rama actual.
Recuerda: guardar un archivo ≠ crear un commit ≠ hacer push. Son acciones distintas.
05

Prueba ideas con ramas

Una rama te permite trabajar en cambios de forma separada antes de integrarlos.

  1. En GitHub Desktop, abre el selector de ramas y crea una llamada mejora-readme.
  2. Añade esta sección al README:
## Proyectos que quiero crear
- Mi primera página web.
- Un organizador de tareas.
- Un pequeño proyecto con inteligencia artificial.
  1. Guarda el archivo, revisa los cambios y crea un commit con el resumen Add future project ideas.
  2. Publica la rama si quieres que esté disponible en GitHub.
  3. Para integrar el cambio, vuelve a la rama principal y utiliza la opción de merge. Comprueba que aparece la sección.
¿No te gusta el cambio? Puedes dejar la rama sin integrar. Una rama no sustituye a una copia de seguridad.

06

Soluciona errores frecuentes

Comprueba en qué parte del flujo estás antes de repetir pasos al azar.

No veo los cambios en GitHub.com

Guarda el archivo. Si hay cambios pendientes, crea un commit. Si el commit existe pero no se ha publicado, usa Push origin y actualiza la página.

No aparece Publish repository

Es posible que el repositorio ya esté publicado. Busca la opción para verlo en GitHub o comprueba si ya tiene un remoto configurado.

El archivo no aparece en Changes

Comprueba que guardaste el archivo, que lo editaste dentro de la carpeta correcta y que seleccionaste el repositorio adecuado. Revisa también las reglas de .gitignore.

Me equivoqué en un commit

Abre History y localiza el commit. Las opciones dependen de si ya se publicó y si otras personas trabajan sobre él. Si ya se compartió, revertirlo suele ser más seguro que reescribir el historial.

Error de autenticación

Comprueba que has iniciado sesión con la cuenta correcta y completa de nuevo la autorización si se solicita. Si persiste, consulta la documentación oficial.

Evita soluciones a ciegas: no ejecutes comandos de borrado, reset o reescritura del historial si no entiendes qué cambios podrían perderse.
07

Tu reto final

Marca las tareas que hayas completado. El objetivo es repetir el proceso por tu cuenta.

Completa las tareas para comprobar tu progreso. La checklist no se envía a ningún servidor.

Después puedes aprender pull requests e issues, publicar una web con GitHub Pages y explorar GitHub Actions.
